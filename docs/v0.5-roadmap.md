# Browser Bridge v0.5 — implementation spec (4 features)

Status: **planned**. Base = v0.4.11 (34 tools). Target = v0.5.0.
User picked all four features below. Build in this order (intercept first — highest leverage).

## Ground rules (from prior sessions)
- User preference: **raw capabilities, NO scope/safety guardrails** — operator is responsible for authorized
  targets (like Burp). Do not add allow-lists, confirmation gates, or target restrictions.
- Operates on the user's **real logged-in Chrome** (real cookies/HttpOnly sessions). For bug-bounty on
  authorized targets. Never submit reports / take destructive account actions unless explicitly asked.
- Version-drift ritual: after any change → `npm run build` (server + extension) → restart launchd service
  (`browser-bridge`) → **reload the unpacked extension** in chrome://extensions. Tools added mid-session
  don't load natively until Claude Code restarts.
- `eval_js` uses `eval` in page context → **blocked by strict CSP** (HackerOne/YesWeHack). Prefer
  `chrome.scripting.executeScript` **function injection** (bypasses page CSP) for anything that must run on
  strict pages. CDP domains are CSP-independent.
- Verify with the `bbcall.py` MCP driver (scratchpad) OR, once restarted, the native `mcp__browser-bridge__*`
  tools. Bump README tool count + version badge; update tool tables.

## Code map (where things live)
- `extension/src/background.ts`
  - `const VERSION = "0.4.11"` → bump to `"0.5.0"`.
  - `dispatch()` — big `switch (msg.type)`; add one `case` per new tool.
  - Injected page funcs named `bbXxx` (e.g. `bbFileUpload`, `bbPasteImage`, `bbLocate`) — self-contained
    functions serialized into the page via `chrome.scripting.executeScript({func, args})`.
  - CDP helpers: `cmd(tabId, method, params)` (sends a CDP command over the attached debugger),
    `ensureAttached(tabId)`, `injectAllFrames`, `injectAllAggregate(tab, func, args)` (runs func in all
    frames, aggregates non-null result), `cdpResolve`, `trustedAction`, `trustedPasteImage`, `doReplay`
    (background-context fetch used by replay_request), `download_resource` handler (Chrome downloads API).
- `server/src/tools.ts`
  - Tool registrations: `server.tool(name, schema, async (args) => {...})` calling `hub.call(name, params)`.
  - Helpers: `tabIdParam`, `textResult(obj)`. fs imports already include
    `writeFileSync, readFileSync, renameSync, copyFileSync, unlinkSync`.
- `extension/manifest.json` — `"version"` (keep in lockstep with VERSION). Permissions already include
  `debugger`, `downloads`, `cookies`? **CHECK**: manifest currently lists
  `["tabs","scripting","storage","alarms","webNavigation","debugger","downloads"]` and
  `host_permissions:["<all_urls>"]`. **`cookies` permission is MISSING** — must add for feature 3.

## Feature 1 — `intercept` (live request/response tampering)  ← build first
The one real Burp-Proxy gap. Uses CDP **Fetch** domain (needs debugger attach → shows the banner; fine).

### Model
A per-tab interception session. Rules are set up front; when a request/response pauses, the extension
records it and either (a) auto-applies a matching rule, or (b) holds it for the agent to resolve.
Because MCP tool calls are request/response (no server push), use a **poll + resolve** model like
`net_get_ws_frames` / `download_status`:

Tools:
- `intercept_start({ tabId, patterns?, stage?, rules? })`
  - `Fetch.enable` with `patterns` (default `[{urlPattern:"*"}]`); `stage` = `"Request"` | `"Response"` |
    `"both"` (Response stage needs `requestStage:"Response"` in the pattern).
  - `rules`: optional array of auto-apply rules, each `{ match:{urlContains?, method?, resourceType?},
    action:"continue"|"fail"|"fulfill"|"modify", set?:{url?,method?,headers?,postData?}, response?:{status?,
    headers?,body?} }`. Store on a per-tab interceptor state object. When a `Fetch.requestPaused` event
    fires, find first matching rule; if none, queue as "pending".
  - Listen to `Fetch.requestPaused` via `chrome.debugger.onEvent`. Each paused event has `requestId`,
    `request{url,method,headers,postData}`, `resourceType`, and (at Response stage) `responseStatusCode`,
    `responseHeaders`. To read a paused **response body**: `Fetch.getResponseBody(requestId)` (base64).
- `intercept_pending({ tabId })` → list queued paused requests `{requestId,url,method,headers,postData,
  stage,resourceType,responseStatusCode?}` (bodies fetched lazily / truncate).
- `intercept_resolve({ tabId, requestId, action, set?, response? })`
  - `continue` → `Fetch.continueRequest({requestId, url?, method?, headers?, postData?})` (headers as
    `[{name,value}]`; postData base64).
  - `fail` → `Fetch.failRequest({requestId, errorReason:"BlockedByClient"})`.
  - `fulfill` → `Fetch.fulfillRequest({requestId, responseCode, responseHeaders, body(base64)})`.
  - `modify` at Response stage → `Fetch.fulfillRequest` with the edited body/status/headers.
- `intercept_stop({ tabId })` → `Fetch.disable`, clear state, optionally auto-detach.

### Gotchas
- Header arrays: CDP wants `[{name,value},...]`, not an object. Convert both ways.
- postData must be base64 for continueRequest; decode `request.postData` (already string) as needed.
- A paused request **blocks the page** until resolved — document that pending requests must be resolved or
  the page hangs. Consider an `autoContinueMs` safety in `intercept_start` (default off, per no-guardrails
  preference — but a very long timeout backstop avoids a wedged tab). Leave OFF unless user wants it.
- Response stage: to get the response you must add a pattern with `requestStage:"Response"`.
- Only one Fetch session per tab; re-`start` replaces.

### Verify
Fixture page + `fetch()` in the page; intercept_start with a rule that rewrites a response body; confirm the
page sees the modified body. Then a pending+resolve round trip (no rule) modifying a request header, echoed
by httpbin-like fixture or a local eval that reflects headers.

## Feature 2 — `fuzz` / intruder (payload iteration + auto-diff)
Built on the existing background-context fetch (`doReplay`). No debugger needed → banner-free.

Tool:
- `fuzz({ tabId?, template, payloads, marker?, concurrency?, headers?, method?, follow?, maxBodyKb? })`
  - `template`: a request spec — either a full URL with `marker` (default `"§"`) placeholders, or an object
    `{url, method, headers, body}` where any field may contain the marker.
  - `payloads`: string[] (or `{name,value}[]`). For each, substitute marker → run one fetch (background
    context, real cookies via `<all_urls>` like replay_request).
  - `concurrency` (default ~10) — run in batches.
  - Collect per payload: `{payload, status, length, timeMs, contentType, snippet}`. 
  - **Auto-diff / anomaly flag**: compute baseline (mode of status + median length); flag rows whose status
    or length deviates (e.g. status != baseline, or length outside ±X%). Return sorted with anomalies first.
  - Reuse the doReplay path so cookies/CSP/CORS are handled identically to replay_request.
- Optional `fuzz` variants later (multi-position clusterbomb) — start with single-marker sniper.

### Gotchas
- Respect `maxBodyKb` cap (default ~64KB) so results don't blow up MCP payload size — store snippet + length,
  not full bodies. Provide `net_get_body`-style follow-up if a full body is needed (or return an id).
- Timing is best-effort (JS `performance.now()` deltas in the bg context — note `Date.now` is fine in the
  extension, only workflow-script sandbox forbids it).

### Verify
Point at a local fixture / a benign endpoint that echoes a path param; feed `["1","2","3","admin"]`; confirm
per-payload status/length and that a differing response is flagged. Pairs with authz_matrix/response_diff.

## Feature 3 — cookies + storage read/write
Two independent tool groups.

### 3a. Cookies (via `chrome.cookies` — ADD `"cookies"` to manifest permissions!)
- `cookies_get({ url?, domain?, name? })` → `chrome.cookies.getAll({url|domain|name})` → return full records
  incl. `httpOnly, secure, sameSite, expirationDate, path, session`. (This is the value-add vs
  identity_capture: real flags, HttpOnly cookies included.)
- `cookies_set({ url, name, value, domain?, path?, secure?, httpOnly?, sameSite?, expirationDate? })` →
  `chrome.cookies.set(...)`.
- `cookies_delete({ url, name })` → `chrome.cookies.remove({url,name})`.
- Run in the **background service worker** (chrome.cookies is an extension API, not page context) — a dispatch
  case that calls chrome.cookies directly, not an injected func.

### 3b. Web storage (injected page func, per tab)
- `storage_dump({ tabId, kinds? })` — inject a func that reads `localStorage` + `sessionStorage` into
  `{local:{...}, session:{...}}`; optionally enumerate IndexedDB DB names via `indexedDB.databases()` and,
  for a named DB/store, dump records. Keep IndexedDB behind an explicit `db`/`store` arg to avoid huge dumps.
- `storage_set({ tabId, area, key, value })` — `area` = `"local"|"session"`; inject
  `window[area+'Storage'].setItem(key,value)`. (`localStorage`/`sessionStorage`.)
- `storage_remove({ tabId, area, key })` and/or `storage_clear({ tabId, area })`.
- Use `injectAllAggregate` or a single-frame inject (top frame usually right for storage; note storage is
  origin-partitioned per frame — default to top frame, allow a `frameOrigin` filter later).

### Gotchas
- chrome.cookies needs the permission — **manifest bump required** → Chrome will show a "new permissions"
  re-enable prompt on reload; warn the user.
- IndexedDB dump can be huge/async — gate it, cap records, and make it opt-in.

### Verify
cookies_get on a logged-in domain shows HttpOnly cookies with flags; set/delete round-trips a test cookie.
storage_dump on a fixture that seeds localStorage; set/remove round-trips.

## Feature 4 — console logs + save_page (MHTML)
### 4a. `console_logs` (own capture; don't depend on claude-in-chrome)
- Options: (i) CDP `Runtime.enable` + `Log.enable`, listen to `Runtime.consoleAPICalled` /
  `Log.entryAdded` (captures console.*, CSP violations, network errors, JS exceptions) into a per-tab ring
  buffer; or (ii) inject a page hook that wraps `console.*` and posts back. **Prefer CDP** — it also gets CSP
  violation reports and uncaught exceptions that a page hook misses, and is CSP-independent.
- `console_start({ tabId })` → enable + start buffering. `console_get({ tabId, pattern?, level?, limit? })` →
  return buffered entries (filter by regex `pattern` like read_console_messages, by `level`); `console_stop`.
- Mirror the net_capture buffering model already in the codebase.

### 4b. `save_page` (MHTML single-file evidence)
- `save_page({ tabId, savePath })` → CDP `Page.captureSnapshot({format:"mhtml"})` → returns `data` (string);
  server writes it to `savePath` (`.mhtml`). One-file, fully self-contained snapshot for reports.
- Alternatively expose `format:"mhtml"` — start with MHTML only. (PDF would be `Page.printToPDF`; add later
  if asked.)

### Verify
console_start → trigger a console.error + a CSP violation on a fixture → console_get shows both. save_page on
any open tab → file exists, opens in Chrome showing the captured page.
